# ClawReflex: product specification and evidence

Updated 2026-11-22. This replaces the original hackathon concept and promotional
copy, which mixed projections with implementation claims. The original is preserved
in the local `v0.1.0-demo` tag (`git show v0.1.0-demo:1.md`).

ClawReflex verifies proposed Python repairs through a RED/reference/GREEN loop.
A probe must produce an assertion failure, with no test errors, on saved source
and pass a trusted independent reference. A candidate must pass the probe,
regression tests and held-out tests. Generated execution must run in an OS sandbox.
Proposals are the default; applying a repair requires an explicit action or repository
opt-in and matching source identity. Rejected runs must preserve developer work.

The historical demo used three owned synthetic fixtures, one sequential agent and
two tool calls. It did not establish arbitrary-repository support, safe host execution,
sub-second latency, parallel analysis, a channel card, or a measured GPU speedup.
The [readiness audit](2026-11-22-clawreflex-product-readiness.md) records the reproduced
issues. The [implementation ledger](clawreflex/IMPLEMENTATION.md) and
[execution plan](plans/clawreflex-product/EXECUTION.md) track fixes and their checks.

## Measured evidence

| Measurement | Observed result | Scope |
| --- | --- | --- |
| Filmed save to done | 173.9 seconds | Real OpenClaw take, including queue waits |
| Best direct two-turn loop | 5.15 seconds | Direct API/tool loop, excludes OpenClaw/capture |
| Cerebras client decode median | 360 tokens/second, n=5 | Trial endpoint under load |
| GPU baseline client decode median | 117 tokens/second, n=3 | Separate runs; not paired wall-time evidence |
| Cold probe / patch | 287.8 / 191.8 milliseconds | Historical demo runner |
| Film duration | 46.0 seconds | Verified with ffprobe; maximum 60 seconds |

The former 1.24–1.35 second loop, <15 millisecond sandbox, 2,000 tokens/second
product rate and 13–46 times wall-clock speedup were projections or unsupported
claims. They are not release evidence. No new live Cerebras benchmark has run in
this implementation session. Queue time, client latency and server decode time
must be reported separately. A decode-rate ratio is not an end-to-end speedup.

## Release targets and judges

- Security: no host effects in the escape corpus, networkless execution, runtime-only
  filesystem mounts, bounded resources, and independent external review.
- Correctness: assertion RED plus trusted reference, then exploit/regression/held-out
  GREEN; no unchanged candidate accepted as a repair.
- Apply: hash-guarded actions, recoverable snapshots and deterministic race tests.
  Filesystem limitations for writers outside the coordination protocol must be stated.
- Generality: configured Python workspaces, isolated runs, no changes outside the
  intended target, and >=80% model repair acceptance over 20 tasks in 3 real repos.
- Performance: paired live n>=30, Cerebras plus two independently identified GPU
  baselines, matched initial requests, bootstrap intervals, p50 <=2 seconds and
  p95 <=5 seconds. Failures and queue delays remain visible.
- Quality: one full test command, >=85% product coverage, >=70% engine mutation
  score, Linux/macOS CI and a fresh install to verified repair within 10 minutes.
- Adoption: a consented 5–10 developer pilot, at least two weeks of observation,
  >=90% install success, >=70% repair acceptance, zero false applies and >=99%
  crash-free sessions. No pilot or external sign-off is implied by implementation.
